# Shopify — Lumen v0.13 platform guide

> **Identity budget on Shopify is ≤ 15% of pixel surface.** Be honest about this. Polaris went GA on October 1, 2025; App Bridge surfaces (title bar, navigation, save bar, modals, toasts) are Shopify-rendered and unstylable. What Lumen can claim, it claims hard. What it can't, it doesn't fight.

## 1. What this platform is

Shopify is the **embedded-app surface** — the Warp shipping app inside a merchant's admin, the Warp checkout shipping calculator on storefronts, the Warp tracking page hosted on the merchant's domain. The Warp products that live here:

- **Warp Shipping for Shopify** — embedded admin app. Carrier rate-shopping at checkout, BOL generation, label printing. The bulk of Lumen-on-Shopify surface area.
- **Warp tracking page** — customer-facing post-purchase tracking embedded on the merchant's storefront. Higher Lumen identity budget (~40%) because it's storefront, not admin.
- **Checkout shipping calculator** — Shopify Checkout UI extension. Identity budget ~5% (Checkout is mostly Shopify chrome).
- **Theme components** — Lumen-themed Liquid snippets a merchant can drop into their custom theme (rate ticker, shipment timeline, lane code badge).

## 2. Token mapping table

Generated output: [`dist/liquid/css-variables.liquid`](../../dist/liquid/css-variables.liquid) — every Lumen semantic variable as a CSS custom property in a Liquid snippet. Merchants drop this into their theme's `assets/` folder, then `{% include 'lumen-tokens' %}` in `theme.liquid` to inject the variables.

### Where Lumen tokens apply

| Surface | Lumen claim | Mechanism |
|---|---|---|
| Embedded admin app (within Shopify iframe) | ✓ Full Lumen contract inside the iframe content | Tokens via `dist/css/lumen.css`; bypass Polaris where the admin app paints its own content |
| Polaris components | ✗ Shopify-painted | Polaris components stay Polaris-painted; don't override CSS variables Polaris uses (`--p-color-*`) |
| App Bridge title bar | ✗ Shopify-painted | Cannot be styled |
| App Bridge nav (left rail) | ✗ Shopify-painted | Cannot be styled |
| App Bridge save bar | ✗ Shopify-painted | Cannot be styled |
| App Bridge modals | ◐ Polaris-rendered chrome; Lumen content inside | Modal frame is Polaris; body content can be Lumen-painted |
| App Bridge toasts | ✗ Shopify-painted | Text is Lumen-voiced; chrome is Shopify |
| Custom action surfaces (button rows, status pills, freight-specific widgets) | ✓ Full Lumen | These are app content, not App Bridge surfaces |
| Checkout UI extension | ◐ ~5% — accent on rate-card, brand voice in labels | Shopify Checkout SDK provides limited theming hooks |
| Tracking page (customer-facing, storefront-embedded) | ✓ ~40% — embedded as iframe with full Lumen contract | Higher claim because it's the merchant's storefront, not admin |
| Liquid theme components | ✓ ~70% — but constrained by theme's parent type system | Themed pages let the merchant override Lumen; that's expected |

### Variable namespacing

To prevent collisions with Polaris and theme variables, Lumen ships with `--lumen-*` prefixed names in Liquid:

```liquid
{%- comment -%}lumen-tokens.liquid — copy this into theme assets/{%- endcomment -%}
<style>
    :root {
        --lumen-surface-canvas: #0d0d0d;
        --lumen-surface-raised: #171717;
        --lumen-text-primary: #fafafa;
        --lumen-action-primary-bg: #00fa8a;
        --lumen-action-primary-fg: #07120d;
        /* …generated by Phase 0 Style Dictionary, one variable per semantic token */
    }
</style>
```

App content references `var(--lumen-surface-canvas)`, not `var(--surface-canvas)`, so a merchant's own theme variables don't collide.

## 3. Identity budget

**Lumen claim on the embedded admin app: ≤ 15% of pixel surface.** This is the verified honest number based on the Polaris GA architecture as of October 1, 2025.

### What Lumen explicitly CAN claim (the 15%)
- **Brand voice** — every line of copy, every error message, every empty-state label, every onboarding flow. Lumen voice (`00-foundations/voice-and-tone.md`) carries fully.
- **Iconography** — Lumen's 1.5px-stroke icon set replaces default Polaris icons in slots where Polaris allows custom icons. Action icons, status indicators, navigation glyphs (where Polaris exposes the slot).
- **Accent color on chips and badges** — Spring Green appears on status chips (Live, On-time, Tendered, Booked) and live-data badges. Polaris allows custom badge colors via `tone="custom"` (when available) or unstyled HTML inside the badge slot.
- **Onboarding illustrations** — first-run flows that occupy the full content area get full Lumen visual control. gpt-image-2 generated assets ship here (Phase 4).
- **Empty-state imagery** — Lumen-style empty states for "no shipments yet", "no rates available", "no carrier selected".
- **The Stat, LiveDot, RateTicker signatures** — these are pure Lumen widgets that can be embedded as React inside the admin app content area.
- **Lane-code typography** — `.lumen-mono` styling on lane codes (LAX→SFO), tracking numbers, ZIP codes, ratesheet rows.

### What Lumen explicitly CANNOT claim
- **Title bar** — Polaris-painted, contains the app name + breadcrumb.
- **Left nav rail** — Polaris-painted, contains the app navigation tree.
- **Save bar** — Polaris-painted, sits at the bottom on dirty forms.
- **Form controls** — Polaris-rendered. Inputs, dropdowns, date pickers, file uploads all use Polaris semantics and Polaris styling. Lumen voice inside (placeholder text, error messages, label copy) but the chrome is Polaris.
- **Layout primitives** — Polaris `<Page>`, `<Card>`, `<Layout>`, `<BlockStack>` shape the page. Lumen lives inside Polaris layout boxes, not alongside them.
- **Toasts** — Polaris `Toast` API. Lumen-voiced text, Polaris-painted surface.
- **Modals** — Polaris `Modal` chrome. Modal body content can be Lumen-painted.

### Storefront tracking page (higher claim)
The customer-facing tracking page is iframed onto the merchant's storefront. There, Lumen claims **~40%** — full Lumen contract for shipment timeline, lane code, status pill, ETA bubble, but the surrounding merchant header / footer is the merchant's theme.

## 4. Glass / blur translation

**None inside the embedded admin app.** Polaris doesn't use vibrancy; Lumen glass surfaces would visually clash with Polaris's flat-card aesthetic. Lumen glass on Shopify admin is a non-starter.

**Glass on the storefront tracking page** is allowed when the merchant's theme supports backdrop-filter. Use a feature-detect:

```css
.lumen-tracking-glass {
    background: rgba(13, 13, 13, 0.5);
}

@supports (backdrop-filter: blur(20px)) {
    .lumen-tracking-glass {
        background: rgba(13, 13, 13, 0.35);
        backdrop-filter: blur(20px) saturate(140%);
        -webkit-backdrop-filter: blur(20px) saturate(140%);
    }
}

@media (prefers-reduced-transparency: reduce) {
    .lumen-tracking-glass {
        background: var(--lumen-surface-raised);
        backdrop-filter: none;
    }
}
```

## 5. Motion translation

### Inside the admin app
- Polaris components animate per Polaris's spec. Don't override.
- Lumen-painted content (Stat, LiveDot, RateTicker, our own React components) follows the Phase 0 motion ladder via CSS — see [`./web.md`](./web.md).
- The LiveDot pulse and RateTicker marquee work but are visually loud against Polaris's calmer aesthetic. Default to muted variants: LiveDot at 0.7× scale amplitude, RateTicker at 1.5× slower speed.

### On the tracking page (storefront)
- Full motion ladder applies — `motion.duration.base` for state transitions, springs for ETA timeline reveals.
- `prefers-reduced-motion` honored per Phase 1 lumen-scoping.css.

### Checkout UI extension
- Shopify Checkout SDK provides limited animation hooks. Mostly Shopify-painted. Don't try to animate; respect the platform.

## 6. Typography translation

### Loading Satoshi on Shopify

Shopify doesn't allow loading external fonts directly. Three viable paths:

**Option A: Upload Satoshi to Shopify Files (recommended for embedded admin app)**

1. Upload `Satoshi-Variable.woff2` and `Satoshi-VariableItalic.woff2` via Settings → Files in the merchant's admin.
2. Reference in `lumen-tokens.liquid`:

```liquid
{%- comment -%}lumen-tokens.liquid{%- endcomment -%}
<style>
    @font-face {
        font-family: 'Satoshi Variable';
        src: url('{{ 'Satoshi-Variable.woff2' | file_url }}') format('woff2');
        font-weight: 300 900;
        font-style: normal;
        font-display: swap;
    }
    @font-face {
        font-family: 'Satoshi Variable';
        src: url('{{ 'Satoshi-VariableItalic.woff2' | file_url }}') format('woff2');
        font-weight: 300 900;
        font-style: italic;
        font-display: swap;
    }
    :root {
        --lumen-font-sans: 'Satoshi Variable', system-ui, sans-serif;
    }
</style>
```

**Option B: Self-host via CDN (recommended for embedded admin app at scale)**

Host the woff2 on the Warp CDN, reference via absolute URL:

```liquid
@font-face {
    font-family: 'Satoshi Variable';
    src: url('https://cdn.warp.dev/lumen/v0.13.0/Satoshi-Variable.woff2') format('woff2');
    ...
}
```

License compliance: ITF-FFL allows self-hosting; do NOT redistribute the woff2 in a public GitHub repo or open-source asset package.

**Option C: Polaris-rendered text** — Polaris components use Shopify's default font stack. Don't override globally; let Polaris components use their own typography. Lumen-painted custom content explicitly opts into Satoshi via `font-family: var(--lumen-font-sans)`.

### OpenType features

Browser support for `font-feature-settings` is universal in modern Chromium / WebKit / Firefox. `tnum`, `lnum`, `zero` all carry verbatim:

```css
.lumen-mono {
    font-family: var(--lumen-font-sans);
    font-feature-settings: 'tnum' 1, 'lnum' 1, 'zero' 1, 'calt' 0;
}
```

## 7. Specific don'ts (Shopify Lumen Law)

- **Don't override Polaris CSS variables.** Polaris components depend on `--p-color-bg-surface`, `--p-color-text`, etc. Overriding them breaks Polaris chrome and gets your app flagged in Shopify's app review.
- **Don't ship Spring Green as a custom theme color in checkout.** Checkout SDK accent colors are reserved for the merchant's brand, not Lumen's.
- **Don't paint into the title bar, save bar, or left nav.** They are App Bridge surfaces. You cannot style them. Trying to creates inconsistency users notice.
- **Don't bypass App Bridge for navigation.** Use `Redirect.toRoute()` and `Redirect.dispatch()` so Shopify can track navigation, render breadcrumbs, and handle deep links. Custom navigation breaks the embedded app contract.
- **Don't ship glass surfaces in the embedded admin app.** Visual clash with Polaris's flat aesthetic; merchant operators will report it as broken.
- **Don't use `display: none` to hide Polaris elements** that you don't want — that approach breaks accessibility. Use App Bridge's API to opt out of surfaces you don't need (e.g., `Page.titleBar` action customization).
- **Don't ship a Lumen Polaris bridge library.** Past designs explored mapping every Polaris component to a Lumen visual override; the 15% identity budget doesn't justify the engineering. Document the integration pattern (this file); ship no bridge code.

### Tracking page (storefront, ~40% Lumen)

The tracking page is a separate iframed app rendered at `tracking.warp.dev` (or the merchant's `tracking.merchant.com` via custom domain). It uses the **full** Phase 2 component graph — `@lumen/shipment-timeline`, `@lumen/lane-code`, `@lumen/live-dot`, `@lumen/stat` — and gets the standard web Lumen experience.

```tsx
import { ShipmentTimeline, LaneCode, LiveDot, Stat } from '@lumen/...';

<div style={{ background: 'var(--surface-canvas)', padding: 24 }}>
    <LaneCode origin="LAX" destination="SFO" rate="$0.42/lb" />
    <ShipmentTimeline events={shipment.events} currentETA={shipment.eta} />
    <Stat value="98.2%" label="ON-TIME DELIVERY" />
    <LiveDot status="live" />
</div>
```

**No separate reference app ships in [`examples/`](../../examples/) for Shopify.** The integration pattern above is the canonical example. The embedded admin app uses the actual Warp Shopify app source (private); the storefront tracking page uses the Phase 2 web component graph verbatim.
